Política de handoff

Umbrales y modo son configuración libre. Para las herramientas el código fija un piso: la configuración solo puede restringir.

Umbral de monto por moneda

Se muestran en unidades mayores; la API las guarda en unidades menores (thresholds_minor). Se acepta cualquier valor mayor o igual a cero.

Modo de handoff

Qué pasa cuando un monto supera el umbral. Se guarda como amount_mode.

Modo de handoff

block: sobre el umbral se exige un handoff prioritario. No bloquea la tarjeta.

Herramientas por estado

Cada herramienta solo puede usarse en los estados que el código permite (su piso). La configuración puede apagarla o volver a encenderla dentro de ese piso, nunca ampliarla.

Relleno: habilitada en ese estado. Contorno: permitida por el código, apagada. Gris con ×: fuera del piso del código.

account.get_summary

Piso del código: VERIFIED · Activa en: ninguno

Apagada

Resumen de cuenta: el segundo flujo (consultas). Arranca deshabilitada y se enciende desde este panel.

card.block

Piso del código: VERIFIED · Activa en: VERIFIED

Activa

Bloqueo de tarjeta con comprobante. El código solo lo permite con identidad verificada.

customer.match

Piso del código: ANONYMOUS, IDENTIFIED · Activa en: ANONYMOUS, IDENTIFIED

Activa

Identificación del cliente por sus datos.

otp.send

Piso del código: IDENTIFIED, OTP_PENDING · Activa en: IDENTIFIED, OTP_PENDING

Activa

Envío del código de verificación (entrega simulada en la demo).

handoff.create

Piso del código: todos los estados · Activa en: todos

Activa

Traspaso a un agente humano. Disponible en todos los estados.

Ampliación rechazada

card.block no puede habilitarse en ANONYMOUS.El código lo permite solo en VERIFIED. La API responde 422: la configuración solo puede restringir.
